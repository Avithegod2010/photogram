# Native re-apply checklist (CNG)

`android/` is gitignored and regenerated by `npx expo prebuild --clean`. Some hand-written
native pieces must be re-applied after any prebuild. This file is the source of truth —
if a rebuild produces an APK without these, they were lost and must be re-applied.

## 0. Constants already handled elsewhere

- Aliyun/Tencent gradle mirrors in `android/build.gradle`, long HTTP timeouts in
  `gradle.properties` (see NEXT_SESSION.md).
- **Memory tuning (8 GB dev machine, added 2026-11-04).** `android/gradle.properties` must
  contain, or the Kotlin daemon dies with "paging file is too small" / Gradle's node helper
  aborts with `NTSTATUS 0xC0000409`:
  ```properties
  org.gradle.jvmargs=-Xmx1536m -XX:MaxMetaspaceSize=384m -XX:ReservedCodeCacheSize=192m
  kotlin.daemon.jvmargs=-Xmx1024m -XX:MaxMetaspaceSize=256m -XX:ReservedCodeCacheSize=128m
  ```
  Also stop WSL (`wsl --shutdown`) and Docker Desktop before building — they hold 1-2 GB.
  Build with `--no-daemon` to avoid stacking daemons.
- **expo-asset must stay on SDK 57.** `expo-audio` declares an `expo-asset: "*"` peer, so a
  bare `npm install` can hoist the SDK 58 build (58.0.18) and break
  `expoAutolinking` settings evaluation ("Field 'version' is required ... Publication").
  `package.json` now pins `expo-asset: ~57.0.20` — never remove it; if npm hoists 58 again,
  run `npx expo install expo-asset`.
- **react-native-fast-tflite needs `-g0` on this machine (added 2026-11-04).** Its debug
  build compiles TFLite headers with `-O1 -g`; with `-g` a single translation unit needs
  >2 GB of commit and clang aborts with `LLVM ERROR: out of memory` / `clang frontend
  command failed due to signal` (the C++ half of People & Pets). Patch
  `node_modules/react-native-fast-tflite/android/build.gradle`:
  ```groovy
  debug {
    cppFlags "-O1 -g0 -fno-var-tracking"
  }
  ```
  then delete `node_modules/react-native-fast-tflite/android/.cxx` and rebuild (the flags are
  baked into `build.ninja`, so a stale `.cxx` keeps the old ones). **This edit lives in
  node_modules — re-apply it after every `npm install`.** The .so ships without debug
  symbols; nothing else changes.
- If the native build still OOMs, compile that module serially instead of in parallel:
  ```
  gradlew :react-native-fast-tflite:configureCMakeDebug --no-daemon
  cd node_modules\react-native-fast-tflite\android\.cxx\Debug\<hash>\arm64-v8a
  E:\Dev\android-sdk\cmake\3.22.1\bin\ninja.exe -j1
  ```
  then run the normal `:app:assembleDebug` — Gradle reuses the finished objects.
- `getForumTopics` edits inside `node_modules/react-native-tdlib` are re-applied by
  `scripts/patch-tdlib.js` (run after `npm install`).

## 1. v0.46 — Backup status widget + quick-settings tile (commit 11a0fe4)

JS side is already in git (`src/lib/widgetState.ts`, autoBackup gating). The native half
lives only in `android/`:

1. **`android/app/src/main/java/com/photogram/app/PhotogramStatusWidget.kt`** —
   AppWidgetProvider reading `files/widget_state.json` (JSON with `line1`, `line2`),
   RemoteViews + tap → MainActivity. Copy the full file from git history? It never was in
   git (android/ ignored) — keep the copy stored in this doc's companion zipped backup or
   re-type from CHANGELOG v0.46 reference. Current on-disk file (2026-10-24) is valid.
2. **`android/app/src/main/java/com/photogram/app/PhotogramTileService.kt`** — TileService
   writing/removing `files/tile_pause`, subtitle "Backup paused"/"Backing up".
3. **`AndroidManifest.xml`** — inside `<application>`:
   ```xml
   <receiver android:name=".PhotogramStatusWidget" android:exported="false">
     <intent-filter><action android:name="android.appwidget.action.APPWIDGET_UPDATE"/></intent-filter>
     <meta-data android:name="android.appwidget.provider" android:resource="@xml/backup_widget_info"/>
   </receiver>
   <service android:name=".PhotogramTileService" android:exported="true"
     android:icon="@mipmap/ic_launcher" android:label="@string/tile_label"
     android:permission="android.permission.BIND_QUICK_SETTINGS_TILE">
     <intent-filter><action android:name="android.service.quicksettings.action.QS_TILE"/></intent-filter>
   </service>
   ```
4. **`res/xml/backup_widget_info.xml`** — appwidget-provider, minWidth 180 dp,
   minHeight 40 dp, updatePeriodMillis 1800000, initialLayout @layout/widget_status,
   resizeMode horizontal|vertical, widgetCategory home_screen.
5. **`res/layout/widget_status.xml`** — vertical LinearLayout (`@+id/widget_root`,
   bg @drawable/widget_bg, children `@+id/widget_title` + `@+id/widget_body`, colors
   #EAF0F6 / #9FB3C8).
6. **`res/drawable/widget_bg.xml`** — rounded 18 dp shape, solid #171E27.
7. **`res/values/strings.xml`** — add `tile_label` ("Pause Photogram backup") and
   `widget_empty` ("Open Photogram to start a backup").

Before re-application, preserve the current files: copy the whole
`android/app/src/main/java/com/photogram/app` + the five res/manifest edits listed above.
(Detailed full text of each: keep a local copy of the files themselves — the working tree
under `android/` is the authoritative copy until the phone verifies v0.46.)

**Verification gates (before trusting on-device):** add widget from launcher picker —
numbers appear within ~30 min or after one auto-backup pass; tile appears under the
quick-settings edit sheet ("Pause Photogram backup"), toggling pauses/resumes NEW queuing
only (visible in Settings → Storage as pending stops dropping).

## 2. Rules

- Never `git add -f android/...` — the CNG policy stands.
- After any prebuild: re-apply §1, re-check mirrors, run the patch script, then a fresh
  compile-only gradle build before chasing runtime bugs.
